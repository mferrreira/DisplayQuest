# DisplayQuest Layout Patterns

## Global page structure

The reference pages use a persistent left navigation area and a horizontal top header.

The main content is divided into:

- primary content area;
- optional secondary information column.

The primary content receives most of the available width.

The secondary column is narrower and contains supporting information.

## Header

The header contains product identity on the left and contextual/global controls toward the right.

The DisplayQuest identity is visually prominent.

The header should remain compact.

Avoid oversized application headers.

## Sidebar

The sidebar is vertical and persistent on desktop.

Navigation items contain:

- icon;
- label;
- active state.

The active navigation item has a lightly tinted background and stronger visual emphasis.

Navigation is intentionally simple.

## Page heading

Pages begin with a clear heading region.

The heading generally contains:

- icon or visual identifier;
- title;
- short description;
- primary action when appropriate.

The heading should not consume excessive vertical space.

## Summary areas

Summary information can appear immediately below the page heading.

The references use compact summary blocks for:

- progress;
- project information;
- ranking;
- upcoming deadlines;
- activity;
- statistics.

Do not force every piece of information into a summary block.

## Main content

The primary content should have the strongest visual hierarchy.

For list-oriented pages such as Projects, use a vertical project list with enough horizontal space to show meaningful project information.

For task-oriented pages, use the Kanban board as the main content rather than surrounding it with unnecessary dashboard widgets.

## Secondary column

The secondary column is used for supporting information such as:

- recent activity;
- upcoming deadlines;
- gamification;
- status summaries;
- secondary statistics.

It should not contain information that competes with the main content.

## Projects page

The Projects reference uses:

- page heading;
- primary "new project" action;
- status filters;
- project search;
- sorting;
- view controls;
- vertical project list;
- overview information in a right-side column.

Each project entry contains several pieces of information without becoming a collection of small cards.

Project entries visually communicate:

- project identity;
- name;
- short description;
- status;
- tags;
- progress;
- members;
- dates;
- contextual actions.

## Home page

The Home reference uses:

- personalized greeting;
- compact summary information;
- Kanban board as the central working area;
- recent activity;
- upcoming deadlines;
- gamification;
- project and progress information.

The Kanban board receives substantially more visual space than secondary widgets.

## Empty space

Whitespace is an intentional part of the design.

Do not fill unused areas simply because space is available.

## Responsive behavior

Preserve the hierarchy when the viewport becomes smaller.

Do not simply compress every desktop column until the content becomes unusable.

Primary content should remain more important than secondary content.
