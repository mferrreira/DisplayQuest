# DisplayQuest Visual Language

## Overall character

The interface is clean, friendly and academic, while retaining a sense of exploration and game-like progression. It ships in a light and a dark theme, and neither is a fallback for the other.

It should feel like a laboratory project management system with its own identity, not like a generic corporate SaaS application.

The interface combines:

- a clean productivity interface;
- restrained accent colors, with tinted neutrals in the dark theme;
- thin outlines;
- subtle depth;
- simple line icons;
- game and exploration references.

## Visual balance

The interface should have a lot of breathing room without becoming visually empty.

Information is organized into clear areas, but the page should not become a wall of bordered cards.

Large sections use whitespace to establish hierarchy.

## Artwork

The interface uses no decorative artwork. Do not add illustrations, stock artwork or handwritten type, and do not read the screenshots as a mandate to draw anything.

The screens carry their identity through layout, typography and the tokens in `app/globals.css`. A region with nothing to say stays empty.

## Color behavior

Color is used to communicate meaning and to create visual rhythm.

In the light theme, pastel colors are preferred for secondary surfaces, tags and status areas. In the dark theme the same role falls to tinted neutrals, and the accent survives as a tint over the surface rather than a saturated fill.

Dark blue is the primary visual anchor.

Green, blue, yellow, purple and other accent colors can distinguish different semantic categories.

Accent colors should remain restrained.

Avoid highly saturated rainbow interfaces.

## Density

The reference interfaces contain substantial information, but information is grouped into readable regions.

Do not remove useful information simply to make the page look minimal.

Do not add decorative information simply to make the page look complete.
